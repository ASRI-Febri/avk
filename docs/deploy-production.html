Tarik Rilis AVK ke Server Produksi

Deployment AVK berjalan satu arah: kode di-push dari komputer developer ke GitHub, lalu server menariknya. Server tidak pernah dipakai mengedit kode — apa pun yang diubah langsung di sana akan hilang saat langkah 3. Ikuti urutan di bawah dari atas ke bawah; tiap langkah menyebutkan tanda berhasilnya.

1

Siapkan sebelum masuk ke server

Kerjakan bagian ini dari komputer developer. Tujuannya memastikan yang akan ditarik server memang sudah lengkap di GitHub.

Pastikan sudah ter-push

Terminal — komputer developerbash
$ git status --short          # harus bersih
$ git fetch -q origin
$ git log --oneline -1
$ git log --oneline -1 origin/main

Dua baris git log terakhir harus menunjuk commit yang sama. Kalau berbeda, berarti masih ada yang belum di-push dan server akan menarik versi lama.

Bila mengubah resources/js atau resources/sass

Aset hasil build ikut di-commit supaya server tidak perlu Node. Jadi build-nya dilakukan di lokal, bukan di server:

Terminal — komputer developerbash
$ npm run production
$ git add -A && git commit -m "Build aset" && git push

Perubahan yang hanya menyentuh Blade, controller, atau route tidak perlu langkah ini.

Catat commit yang sedang berjalan

Berguna untuk rollback. Setelah masuk server nanti, jalankan git rev-parse --short HEAD sebelum menarik, lalu simpan angkanya.

2

RDP ke server

Masuk ke Windows Server lewat Remote Desktop, lalu buka PowerShell. Deployment tidak bisa dijalankan dari luar — hanya port RDP yang terbuka ke server ini.

Server punya dua XAMPP

C:\xampp berisi PHP 5 untuk aplikasi lama, C:\xampp7 berisi PHP 7 untuk AVK. Karena itu jangan pernah memanggil php polos — bisa mengarah ke PHP 5 dan gagal. Selalu pakai path lengkap.

PowerShell — serverpemeriksaan awal
PS> C:\xampp7\php\php.exe --version     # harus 7.x
PS> cd C:\xampp7\htdocs\avk
PS> git rev-parse --short HEAD          # catat untuk rollback
3

Jalankan deploy.ps1

Satu perintah ini mengerjakan seluruh urutannya: aplikasi masuk mode perbaikan, kode ditarik, dependency dipasang, cache dibersihkan, lalu aplikasi kembali online.

PowerShell — serverdeploy
PS> powershell -ExecutionPolicy Bypass -File C:\xampp7\htdocs\avk\deploy.ps1

Yang dikerjakan script, berurutan

  1. Memastikan php.exe yang dipakai benar-benar PHP 7, berhenti bila bukan.
  2. php artisan down — pengguna melihat halaman perbaikan.
  3. git fetch lalu git reset --hard origin/main.
  4. composer install --no-dev --optimize-autoloader.
  5. config:clear, route:clear, view:clear, cache:clear.
  6. php artisan up — selalu dijalankan, bahkan bila ada langkah yang gagal.
  7. Menampilkan daftar file .sql yang berubah sebagai pengingat langkah 4.
reset --hard membuang perubahan lokal

Semua file ter-track yang diedit langsung di server akan hilang tanpa konfirmasi. .env, vendor/, dan node_modules/ aman karena di-gitignore.

Tanda berhasil: baris DEPLOY SELESAI berwarna cyan, dan sebelumnya muncul perpindahan commit seperti d9af9a1 -> e6a64f2.

4

Terapkan stored procedure yang berubah

Basis data terpisah dari repo, jadi deploy.ps1 tidak menyentuhnya. Di akhir jalannya, script menampilkan daftar file SQL yang berubah:

PowerShell — serverkeluaran deploy.ps1
!!  ADA PERUBAHAN SQL - terapkan manual ke SQL Server (SSMS):
      SQLStoredProcedure/USP_MC_ValasStock_List.sql

Buka tiap file itu di SSMS, sambungkan ke AVKDB, lalu jalankan isinya. File di repo sudah memakai pola DROP lalu CREATE, jadi aman dijalankan ulang.

Cara memastikan sebuah stored procedure sudah terpasang:

SSMS — AVKDBsql
SELECT name, modify_date
FROM sys.objects
WHERE name = 'USP_MC_ValasStock_List';
Untuk rilis e6a64f2

Stored procedure USP_MC_ValasStock_List sudah diterapkan ke AVKDB pada 15 Agustus 2026. Pengingat SQL dari script boleh diabaikan untuk rilis ini.

5

Verifikasi hasilnya

Jangan tutup RDP sebelum empat hal ini terlihat benar dari browser.

  • Halaman /login terbuka normal, bukan halaman perbaikan. Bila masih tertahan, jalankan C:\xampp7\php\php.exe artisan up.
  • Commit di server sama dengan di GitHub — bandingkan keluaran git rev-parse --short HEAD di server dengan commit terakhir di repo.
  • Fitur baru rilis ini muncul: buka mc-sales-quick/create, kolom Sisa Stok harus ada di tabel detail dan terisi begitu valas dipilih.
  • Satu transaksi lama masih bisa dibuka tanpa error, misalnya lewat menu mc-sales-order.

Bila ada halaman yang menampilkan error setelah deploy, bersihkan cache sekali lagi sebelum menyimpulkan rilisnya bermasalah:

PowerShell — serverbersihkan cache
PS> cd C:\xampp7\htdocs\avk
PS> C:\xampp7\php\php.exe artisan view:clear
PS> C:\xampp7\php\php.exe artisan config:clear
6

Rollback bila rilis bermasalah

Kembalikan ke commit yang dicatat di langkah 2. Kode kembali seperti semula dalam hitungan detik.

PowerShell — serverrollback
PS> cd C:\xampp7\htdocs\avk
PS> git reset --hard <commit-lama>
PS> C:\xampp7\php\php.exe artisan view:clear
PS> C:\xampp7\php\php.exe artisan up
Basis data tidak ikut mundur

Stored procedure yang sudah diterapkan tetap versi baru. Umumnya aman karena SP baru dirancang tetap melayani kode lama, tapi bila sebuah SP diubah bentuk hasilnya, jalankan ulang versi lamanya dari riwayat git file .sql tersebut.

Cara manual, bila deploy.ps1 tidak bisa dipakai

Urutan yang sama, diketik satu per satu. Pakai ini hanya saat script gagal jalan — misalnya ExecutionPolicy diblokir kebijakan domain.

PowerShell — servermanual
PS> cd C:\xampp7\htdocs\avk
PS> C:\xampp7\php\php.exe artisan down --retry=15
PS> git fetch --all --prune
PS> git reset --hard origin/main
PS> C:\xampp7\php\php.exe composer.phar install --no-dev --optimize-autoloader
PS> C:\xampp7\php\php.exe artisan config:clear
PS> C:\xampp7\php\php.exe artisan route:clear
PS> C:\xampp7\php\php.exe artisan view:clear
PS> C:\xampp7\php\php.exe artisan cache:clear
PS> C:\xampp7\php\php.exe artisan up

route:cache sengaja tidak dipakai: sebagian route memakai closure, dan Laravel 7 gagal men-cache route bila ada closure.

Kegagalan yang pernah terjadi di server ini

Semua baris di bawah pernah benar-benar muncul, bukan daftar kemungkinan.

PesanSebabnyaPerbaikan
PHP yang terpakai versi 5.x Perintah php polos mengarah ke C:\xampp (PHP 5). Pakai C:\xampp7\php\php.exe. Di deploy.ps1, periksa variabel $Php menunjuk file php.exe, bukan foldernya.
error: invalid path …
fatal: Could not reset index file		 Ada file yang di-commit dari mac dengan karakter ilegal di Windows (\ : * ? " < > |). Perbaiki nama file di lokal lalu push ulang. Cek sebelum commit dengan git ls-files | grep '\\'.
composer.phar tidak ditemukan Composer tidak ada di lokasi yang dicari script. Script tetap lanjut memakai vendor/ yang ada. Bila composer.lock berubah, pasang composer lalu isi variabel $Composer.
Diminta login GitHub berulang Personal Access Token belum tersimpan di Credential Manager. Saat diminta, isi username GitHub dan tempel token sebagai password — setelah itu tersimpan.
Halaman perbaikan tidak hilang artisan up gagal karena error sebelumnya. C:\xampp7\php\php.exe artisan up, atau hapus storage\framework\down.
Tampilan lama masih muncul Blade yang ter-compile masih versi lama, atau cache browser. artisan view:clear di server, lalu muat ulang keras (Ctrl+F5) di browser.
Permission denied pada storage\ User Apache tidak punya akses tulis. Beri akses tulis ke storage\ dan bootstrap\cache\. Cukup sekali, tidak berubah oleh pull.

Setup pertama kali

Hanya dijalankan bila folder aplikasi di server belum terhubung ke GitHub — misalnya hasil copy-paste manual. Sesudah ini, deployment berikutnya cukup langkah 1–5.

Backup dulu

git reset --hard di bawah menimpa file yang ter-track. Pastikan seluruh perubahan yang ada di server sudah lebih dulu masuk repo.

PowerShell — serversatu kali saja
PS> Compress-Archive C:\xampp7\htdocs\avk C:\backup\avk-sebelum-git.zip
PS> cd C:\xampp7\htdocs\avk
PS> git init
PS> git remote add origin https://github.com/ASRI-Febri/avk.git
PS> git fetch origin        # isi username + PAT saat diminta
PS> git reset --hard origin/main
PS> git remote -v           # pastikan menunjuk repo avk

Token GitHub dibuat di Settings → Developer settings → Fine-grained tokens dengan akses Contents: Read-only untuk repo avk. Alternatif yang lebih aman: deploy key SSH khusus server.
